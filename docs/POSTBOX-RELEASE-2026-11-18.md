## Запись, очередь и отправка

Целевой маршрут: браузер → общая Yandex Function → YDB `ru-central1` → закрытая Yandex Function `postbox.drain` → Yandex Cloud Postbox → `TheAlexMay@yandex.ru`.

1. Сервер проверяет Origin, форму, поля и редакцию согласия.
2. Одна `serializableReadWrite` транзакция проверяет ID и записывает **INSERT** в `leads`, `consent_events`, `notification_outbox`. Нельзя получить письмо для заявки без успешно зафиксированного согласия.
3. После commit посетитель получает `202 {ok:true,stored:true,submissionId,notification:"pending"}`. SMTP/Postbox не вызывается в запросе посетителя. Ошибка базы до commit остаётся ошибкой заявки.
4. Повтор того же ID и неизменных данных возвращает 200 / `already-recorded`. Не меняет исходные время, согласие, статус, заметки и очередь. Другие данные под занятым ID дают 409. Существующий исторический ID без outbox не создаёт задание при повторе.
5. Закрытый отправитель забирает до пяти готовых ID, фиксирует захват транзакцией, затем вызывает Postbox. Никаких клиентских полей в mail API нет. Повторный конкурентный захват занятого задания невозможен.

`notification_outbox`: PK `submission_id`; `site_host`, `fingerprint` нормализованного ввода, `state`, `server_received_at`, `expires_at`, `message_id`. Отпечаток не является токеном доступа и не попадает в письмо/журналы. TTL очереди — один год от первоначального приёма; сроки lead (год) и доказательства согласия (три года) сохранены. Таблица создаётся без backfill, существующие `leads`/`consent_events` не мигрируют. Окончательное удаление в основной базе удаляет очередь, meta, consent и lead одним DML-запросом. Межбазовая маршрутизация и отказ при неоднозначном ID в CRM сохранены.

| Состояние | Дальнейшее действие |
|---|---|
| `postbox-pending` | Готово к первой отправке |
| `postbox-sending-1/2/3` | Захват зафиксирован **до** внешнего запроса. Автоматически не освобождается |
| `postbox-sent` | API вернул 200 и MessageId; это приём Postbox, **не подтверждение Delivery** |
| `postbox-retry-1/2` | Только явный 429 или ошибка до соединения; всего не более трёх попыток |
| `postbox-failed` | Окончательный 4xx (кроме 408/429), неверные метаданные или исчерпанные безопасные повторы |
| `postbox-uncertain` | Тайм-аут, обрыв ответа, 5xx/408, неожиданный ответ или 200 без читаемого MessageId. Автоповтора нет |
| `disabled` | Заявка сохранена при `storage-only` или `notifications:false`, автоматического включения в очередь нет |

Если письмо было принято, но запись результата не удалась, остаётся `postbox-sending-N`; таймер его не отправляет повторно. Это осознанный выбор в пользу отсутствия автоматических дублей. Абсолютную доставку ровно один раз при неопределённом сетевом результате API обеспечить нельзя — требуется ручная сверка.

Проверять `uncertain` и зависшие `sending` вручную в закрытой YDB и Postbox: сопоставить MessageId (если получен), получателя, время, домен и заголовок `X-Submission-Id`; затем проверить письмо в ящике по ID в тексте. При наличии Delivery/письма повтор запрещён. Отсутствие события само по себе не доказывает, что письмо не отправлено. Состояния нельзя автоматически возвращать в pending по возрасту. Любой ручной повтор — только после установленного отказа и решения владельца.

## Почтовый шаблон

Переменные **только на закрытом отправителе**:

```text
DELIVERY_MODE=postbox
POSTBOX_FROM_EMAIL=notifications@prointeriors.ru
POSTBOX_TO_EMAIL=TheAlexMay@yandex.ru
ENDPOINT=<сохранить действующий основной YDB endpoint>
DATABASE=<сохранить действующую основную YDB>
```

Тема: `Новая заявка с сайта photoprobiz.ru` либо `Новая заявка с сайта aleksreport.ru`.
HTML и plain text: домен, ID, время получения сервером в МСК; кнопка «Открыть заявку» и обычная ссылка:
`https://functions.yandexcloud.net/d4e5ur2fo156lrcve6id?admin=1&lead=<ID>`.
Заголовки `X-Submission-Id` и `X-Source-Site` повторяют ID/домен для сверки неопределённого ответа. Имена, телефоны, email клиента, предпочтение связи, пакет, расчёт, bookingDetails, заметки и доказательство согласия не передаются.

CRM-shell доступен публично, но API карточки без подписанной сессии отвечает 401. Пароль или сессия не помещаются в ссылку. Вызов Postbox использует IAM-токен контекста `X-YaCloud-SubjectToken`, без статических ключей. Требуются тот же каталог отправителя и роль `postbox.sender`. Формат сверён с [официальным SendEmail API](https://yandex.cloud/en/docs/postbox/aws-compatible-api/api-ref/send-email) и [аутентификацией Postbox](https://yandex.cloud/ru/docs/postbox/api-ref/authentication).

## Остановка / откат

Быстрая остановка почты: выключить новый минутный таймер и установить `DELIVERY_MODE=storage-only` на закрытом отправителе. Чтобы перестать добавлять новые задания, тот же режим на общем приёмнике; формы продолжают сохранять заявку и согласие с успешным ответом. pending остаются для последующего решения, uncertain/sending не сбрасываются. Не запускать backfill и не превращать disabled в pending массовым запросом.

После переключения документов не откатывать вслепую на старый relay-код: он не знает новых версий и вернёт Cloudflare/Telegram в маршрут. Если нужен полный возврат, согласовать одновременный возврат документов обоих сайтов, поддерживаемых версий сервера и сохранность очереди. Предпочтителен кандидат в режиме storage-only с последующим исправлением, без восстановления старых данных поверх новых.
