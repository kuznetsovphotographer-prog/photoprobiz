# photoprobiz.ru — автономная локальная версия

React + TypeScript + Vite. Источник дизайна и содержания — опубликованный photoprobiz.ru, исследованный 7 сентября 2026 года. Проект работает без Tilda, Google Fonts, внешнего хранилища фотографий и сервера заявок.

## Запуск на Windows

Откройте терминал в `D:\Antigravity\Sites\photoprobiz`:

```powershell
npm install
npm run dev
```

Откройте адрес, показанный Vite, обычно http://127.0.0.1:5173/.

Проверенная production-версия:

```powershell
npm run build
npm run preview
```

Адрес: http://127.0.0.1:4173/. Остановить сервер: Ctrl+C. Если порт занят: `npm run preview -- --port 4174`. После изменений для production-preview снова выполните `npm run build`; сервер перечитывает обновлённые файлы. Для воспроизводимой установки с сохранёнными версиями используйте `npm ci`.

Для ручного просмотра с устройств в той же Wi‑Fi сети используйте `npm run preview:lan`; удобнее запускать `ОТКРЫТЬ-САЙТ.cmd`, потому что он сам соберёт сайт и покажет подходящий сетевой адрес.

Нужен Node.js 22.12+ или поддерживаемая более новая версия. Интернет нужен для первоначальной установки пакетов; после установки все страницы, фото, шрифты, диалоги, формы и PDF работают через локальный сервер без интернета. Внешние ссылки на соцсети и звонок сохраняют своё исходное назначение. Открытие HTML двойным щелчком через `file://` не заменяет HTTP-сервер.

## Просмотр в локальной сети

Дважды щёлкните `ОТКРЫТЬ-САЙТ.cmd` в корне проекта (английский ярлык — `START-LOCAL-NETWORK-SITE.cmd`). Скрипт собирает сайт, запускает сервер на этом компьютере и выводит адрес вида `http://192.168.x.x:4173/`. Этот адрес автоматически копируется в буфер: его можно отправить или открыть с телефона и компьютера, подключённых к той же Wi‑Fi или проводной локальной сети.

Сервер не создаёт внешнюю ссылку и не использует Cloudflare. Он работает только пока открыто окно скрипта и компьютер включён. Закрытие окна или Ctrl+C останавливает сервер. Если Windows спросит о доступе к сети, разрешите Node.js только для частных сетей. Скрипт откажется запускаться, если порт 4173 уже занят, чтобы не затронуть другой локальный сервис. Файл `ОТКРЫТЬ-САЙТ.html` служит вспомогательной страницей: он открывает сайт, если сервер уже работает, и подсказывает, какой cmd-файл запустить, если нет.

Адреса страниц без завершающего `/` открываются с нормализацией URL. Политика конфиденциальности, контакты, четыре формы, меню и галереи открываются так же, как в оригинале, поверх главной. Отдельная публичная оферта в доступных страницах и локальных материалах не обнаружена; текст не придумывался. Политика перенесена полностью.

Гайд: `public/downloads/business-portrait-checklist.pdf`. Это исходный шестистраничный PDF, совпадающий по SHA-256 с документом сайта. В главном меню ссылки на него нет. Прямое открытие благодарности и PDF остаётся возможным, как у исходного сайта; защита доступа сервером сейчас не добавлена.

## Архитектура и редактирование

- `src/App.tsx`, `src/components/DesignSection.tsx` — статическая композиция. Большая часть страницы предварительно строится в HTML и не гидратируется в браузере.
- `src/data/sections.json` — порядок секций, тексты, ссылки, изображения и вложенные группы. Поле `id` — понятное имя секции; `className: n…` связывает элемент с его измеренным оформлением.
- `src/styles/composition.css` — геометрия оригинала на базовых ширинах 320, 480, 640, 960, 961 и 1200 px. На телефоне сохранено масштабирование исходной композиции; первый экран и элементы, привязанные к окну, имеют отдельные правила.
- `src/styles/base.css` и стили компонентов — общие правила, интерактивные состояния, доступность и собственные компоненты.
- `src/data/assets.json` — соответствие исходных URL локальным оптимизированным файлам. Старые URL здесь являются справочными ключами; браузер их не запрашивает.
- `src/data/galleries.json` — 17 галерей, 242 фотографии в исходном порядке, описания и responsive-варианты.
- `src/components/LeadForm.tsx`, `src/services/lead.ts` — формы и отдельный транспорт заявок.
- `src/components/Dialog.tsx` — закрытие, Escape, ловушка фокуса, блокировка фона, вложенные окна и восстановление фокуса.
- `src/data/privacy.ts`, `src/pages/ThankYouPage.tsx` — политика и благодарность.
- `src/data/seo.json`, `scripts/prerender.tsx` — метаданные и предварительное построение HTML.
- `src/data/servicePages.ts`, `src/pages/ServicePage.tsx` — содержание и общий шаблон четырёх индексируемых страниц услуг.
- `public/` — фотографии, иконки, шрифты с лицензиями, favicon, PDF, robots и sitemap.
- `audit/`, `output/playwright/` — локальная карта источника, измерения и снимки сравнения; они не включаются в `dist` и Git-репозиторий.

При редактировании статических данных или композиции во время `npm run dev` выполните в другом терминале `npm run prerender`, чтобы обновить HTML; CSS и интерактивные компоненты Vite обновляет автоматически.

Чтобы изменить текст, найдите точную фразу в `src/data/sections.json` и измените соответствующий `html`. Для цены правьте её видимый текст и отдельно осознанно проверьте `src/data/seo.json`. Чтобы заменить фото, укажите подготовленный локальный `src`, `srcSet`, размеры и `alt` в нужном узле или галерее. Не подменяйте оригинальный файл внутри папки исходных фотографий.

Для изменения отступов найдите `className` элемента и его правило в `composition.css`. Для новых самостоятельных секций удобно создавать обычные React-компоненты с собственным CSS. Генератор `scripts/compile-design.py` был нужен для точного первоначального переноса; обычные `npm run dev/build` его не запускают. Повторный запуск генератора перезапишет измеренные `sections.json` и `composition.css`, поэтому сначала сохраните сделанные вручную изменения.

## Ресурсы и скорость

Первый экран использует AVIF с WebP-резервом. Остальные фотографии имеют WebP-варианты без увеличения исходного размера, корректные `srcset`/`sizes`, ширину и высоту. Только фотография первого экрана имеет высокий приоритет и responsive preload. Остальные используют lazy loading и низкий сетевой приоритет. Сохранены индивидуальные кадрирования, включая нестандартный масштаб фоновых фотографий. Иконки — локальные/встроенные SVG; шрифты — локальные WOFF2.

Галереи, контакты, политика и мобильное меню подгружаются по запросу. В production нет Tilda runtime, jQuery, Google Fonts, аналитики и отправки в сервис Tilda. Локальный сервер `scripts/serve.mjs` использует Brotli/gzip, ETag и кэширование файлов с хешем в имени; это небольшой статический сервер на встроенных модулях Node.js.

`scripts/optimize-assets.mjs` воспроизводит подготовку ресурсов по проверенному сопоставлению. Он использует Sharp из установленного пакета или из доступного на этом компьютере runtime Codex. Готовые ресурсы уже включены в проект, поэтому Sharp и Python не нужны для запуска и сборки сайта. Для переноса самого оптимизатора на другую машину установите Sharp отдельно либо задайте путь `CODEX_NODE_MODULES` к папке с ним.

## Формы сейчас и будущий Worker

По умолчанию `VITE_LEAD_ENDPOINT` не задан. Форма проверяет поля, отображает ошибки, блокирует повторную отправку во время обработки и через mock-адаптер открывает благодарность. Никаких заявок фотографу не отправляется. Контактные данные не сохраняются; sessionStorage содержит только маркер успешного mock-сценария. Все 205 вариантов страны и маски телефона доступны локально.

Будущий транспорт находится в `src/services/lead.ts`. После создания Worker можно задать в `.env.local`:

```dotenv
VITE_LEAD_ENDPOINT=https://your-worker.example/api/lead
```

Это переключит адаптер на POST. Текущий payload соответствует реальным полям: `name`, `contact`, `contactMethod`, `consent`, `packageName`, `source`, `phoneCountry`. При интеграции добавьте на границе транспорта `page` и `createdAt`, если они нужны серверу. Worker должен самостоятельно валидировать payload и ответ, ограничивать частоту запросов, проверять CORS и обрабатывать ошибки Telegram. Telegram Bot Token хранится только в секретах Worker. Сейчас Worker, бот и внешняя отправка не подключены.

## SEO

Главная, страницы услуг и служебные страницы генерируются в HTML при сборке. Тексты, заголовки, title, description, canonical, Open Graph, Twitter Card и JSON-LD доступны без JavaScript. На главной используется один H1, а устаревший meta keywords удалён. Alt и порядок фотографий сохранены. Фавикон, robots.txt и расширенный sitemap с изображениями находятся в `public/`.

Для поисковых нейросетей явно разрешены `OAI-SearchBot` и `Claude-SearchBot`; служебные страницы для них закрыты так же, как для обычных роботов. В корне генерируется экспериментальный `llms.txt`, а в `public/ai/` — краткие Markdown-версии главной информации и каждой услуги. Индексируемые HTML-страницы ссылаются на эти материалы через `rel="describedby"` и `rel="alternate"`. Основным источником для поисковой индексации остаются канонические HTML-страницы, sitemap и структурированные данные.

На главной сохранены релевантные LocalBusiness, Person и FAQPage и добавлена WebSite. Минимальная цена в Offer соответствует пакету 15 000 ₽. Каждая страница услуги получает собственную Service schema; на 404, cookie и thank-you коммерческая разметка не выводится, эти страницы закрыты от индексации. При будущем изменении домена обновите canonical/OG/JSON-LD и адрес sitemap в `scripts/prerender.tsx` / `src/data/seo.json`.

## GitHub Pages на следующем этапе

Публиковать следует содержимое `dist` после `npm ci` и `npm run build`. Сборка использует относительную базу Vite, статические HTML-страницы и директории реальных URL. Перед публикацией под путём репозитория отдельно проверьте базовые URL, канонический домен и пути в метаданных; перед публикацией на photoprobiz.ru оставьте канонический домен. GitHub Pages и пользовательский домен в этой работе не подключались. Node-сервер для Pages не нужен.

Готовый workflow и пошаговая инструкция: [`GITHUB-PAGES-PUBLISH.md`](GITHUB-PAGES-PUBLISH.md). После включения GitHub Pages каждый push в `main` автоматически запускает тесты, сборку и публикацию.
