# Yandex Cloud Functions: photoprobiz-leads

Действующая функция: `https://functions.yandexcloud.net/d4e5ur2fo156lrcve6id`.

Режим: `DELIVERY_MODE=cloudflare-relay`. Браузер → Яндекс → существующий Cloudflare Worker → Telegram. Прямые обращения Яндекса к Telegram при проверке 10.09.2026 завершались таймаутом, включая IPv4. Серверная пересылка через Worker проверена: HTTP 200, `ok: true`. Cloudflare Worker остаётся необходимым для доставки; удалять его нельзя.

## Загрузка в консоли

1. В редакторе функции выберите Node.js 22, источник «ZIP-архив».
2. Загрузите `output/photoprobiz-leads.zip` из корня проекта. В архиве только `index.js` и `package.json`, без секретов.
3. Точка входа: `index.handler`.
4. Таймаут: 15 секунд. Память: 128 МБ.
5. Сеть и сервисный аккаунт для этой версии не выбирайте: она обращается только к внешнему Telegram API.
6. В переменных окружения задайте `DELIVERY_MODE` = `cloudflare-relay`. В этом режиме Telegram-секреты использует существующий Cloudflare Worker; Яндекс их ему не передаёт. Режим прямой доставки (без этой переменной) требует `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, но пока не подходит из-за сетевых таймаутов. Уже введённые Telegram-переменные не используются в режиме пересылки. Секреты не включайте в код, ZIP, Git или скриншоты.
7. Сохраните изменения и дождитесь готовности версии. Затем в «Обзоре» разрешите публичный вызов функции: посетителям сайта нужна возможность вызвать её без учётной записи Яндекса. Это не открывает доступ к редактированию функции или её переменным.
8. Скопируйте «Ссылку для вызова». Используйте её напрямую, без добавления `/lead` или `/health`.

GET по этой ссылке возвращает проверку работоспособности (`ok`, `provider`, `deliveryMode`, `telegramConfigured`). `telegramConfigured` отражает наличие переменных для прямого режима, а не живую проверку доставки. POST принимает заявку; OPTIONS обслуживает CORS. Успех возвращается только после подтверждения обработчика доставки. Обращение к следующему серверу прерывается через 8 секунд. Автоматических повторных отправок нет: при таймауте доставка может быть неопределённой, повторная ручная отправка может дать дубликат.

Проверки origin ограничивают браузерные источники, но не являются полноценной защитой от ботов. Настройте уведомления о расходах и наблюдайте за нагрузкой публичной функции.

## До переключения рабочего сайта

- Открыть ссылку функции по Wi-Fi и через Beeline без VPN; получить `deliveryMode: cloudflare-relay`.
- Проверить CORS с origin `https://photoprobiz.ru` и тестовую доставку в существующий Telegram-чат.
- Затем заменить `VITE_LEAD_ENDPOINT` в `.github/workflows/deploy-pages.yml` на прямую ссылку функции, выполнить тесты и сборку, опубликовать GitHub Pages.
- На опубликованном сайте проверить обе формы, варианты мессенджеров/пакетов, страницу благодарности и PDF. Отдельно подтвердить доставку по Beeline.
- Сохранить действующий Worker: он необходим и после переключения. Домен сайта и DNS GitHub Pages менять не требуется.

## Локальные тесты

`node --test yandex/lead-function/index.test.cjs`

Тесты используют подставной Telegram API и не отправляют сообщений. Они проверяют поля всех форм и способов связи, CORS, base64-события, ошибки, отсутствие секретов и таймауты. Живая доступность Яндекса и Telegram подтверждается только после загрузки функции.
