# Заявки с сайта в Telegram через Яндекс и Cloudflare

Практическая инструкция для следующих сайтов Александра. Подготовлена 10 сентября 2026 года по рабочему проекту photoprobiz. Названия пунктов кабинетов, тарифы и доступность сетей со временем могут меняться.

## 1. Что именно мы повторяем

**Cloudflare участвует и остаётся обязательной частью этой схемы.** Яндекс принимает заявку от посетителя. Cloudflare Worker получает её от Яндекса и отправляет сообщение через Telegram Bot API.

```text
Посетитель с телефона или компьютера
  │
  ├── открывает сайт → GitHub Pages или другой хостинг
  │
  └── отправляет форму → HTTPS-адрес Yandex Cloud Function
                           │
                           └── серверный запрос → Cloudflare Worker
                                                    │
                                                    └── Telegram Bot API → ваш чат
```

Телефон посетителя не соединяется ни с Cloudflare Worker, ни с Telegram API. Это устраняет зависимость отправки формы от доступности Cloudflare у мобильного оператора. При этом соединение **Яндекс → Cloudflare** тоже должно работать: его проверяем отдельно для каждого нового проекта.

Сам сайт можно оставить на GitHub Pages. Перенос сайта на Яндекс и покупка нового домена для этой схемы не нужны. Если сайт сам недоступен у оператора, эта схема формы не решит проблему загрузки сайта.

### Почему не просто Яндекс → Telegram

В проверках photoprobiz прямые запросы из Yandex Cloud Function к Telegram завершались таймаутом. Отдельная проверка по IPv4 тоже зависала, хотя обычный выход в интернет из функции работал. Через существующий Cloudflare Worker тестовая заявка получила подтверждение примерно за 1,45 секунды, а владелец подтвердил получение сообщения.

Это результат конкретной проверки, а не утверждение о постоянной блокировке Telegram во всём Yandex Cloud. Для повторения проверенной схемы используйте режим `cloudflare-relay`.

### Действующие значения photoprobiz

| Назначение | Значение |
|---|---|
| Сайт | `https://photoprobiz.ru` |
| Yandex Function | `photoprobiz-leads` |
| URL функции, который вызывает браузер | `https://functions.yandexcloud.net/d4e5ur2fo156lrcve6id` |
| Режим функции | `DELIVERY_MODE=cloudflare-relay` |
| Cloudflare Worker | `photoprobiz-lead-form` |
| URL Worker для заявки | `https://api.photoprobiz.ru/lead` |
| Проверка Worker | `https://api.photoprobiz.ru/health` |
| Сборка сайта | `.github/workflows/deploy-pages.yml` |
| Переменная адреса формы | `VITE_LEAD_ENDPOINT` |

На момент подготовки инструкции пользователь подтвердил открытие URL Яндекса через Beeline без VPN и получение тестового сообщения. После публикации обе формы сайта проверены в браузере, страница благодарности открывается, PDF отвечает HTTP 200. Полную отправку опубликованной формы через конкретную SIM нужно подтверждать отдельно.

## 2. Что потребуется для нового сайта

- Аккаунт Yandex Cloud с действующим платёжным аккаунтом и каталогом.
- Аккаунт Cloudflare с возможностью публиковать Workers.
- Telegram-бот и ID чата получателя.
- Исходники нового сайта и доступ к его публикации.
- Node.js и npm на компьютере для сборки Worker и проверок.

Для разных сайтов удобнее создавать отдельные функцию и Worker: например, `interiors-leads` и `interiors-lead-form`. Один аккаунт Яндекса и один аккаунт Cloudflare можно использовать для нескольких проектов. Бот может быть отдельным или общим, но текст сообщения должен однозначно указывать сайт.

Не создавайте новый Worker с именем существующего рабочего Worker: публикация по прежнему имени обновит действующий обработчик.

### Какие файлы взять за основу

Скопируйте в новый проект исходники из этого проекта:

```text
cloudflare/lead-worker/
  src/index.ts
  wrangler.jsonc
  package.json
  package-lock.json
  tsconfig.json

yandex/lead-function/
  index.js
  package.json
```

Не копируйте `node_modules`, `.wrangler`, файлы секретов и сгенерированный `worker-configuration.d.ts`. Зависимости и типы создаются заново. Общая логика клиентской формы находится в `src/services/lead.ts`, пример интерфейса — в `src/components/LeadForm.tsx`.

Готовый ZIP для photoprobiz нельзя просто подключить к другому сайту: внутри кода сейчас зафиксированы домены, адрес Worker и допустимые поля. Сначала выполните замены из следующих разделов, затем соберите свой ZIP.

## 3. Telegram: подготовить бота и получателя

1. Откройте официального [@BotFather](https://t.me/BotFather).
2. Если нужен отдельный бот, отправьте `/newbot` и задайте имя и username. Если используете существующего, новый создавать не нужно.
3. Сохраните токен бота в менеджере паролей или в защищённом локальном месте вне репозитория.
4. Откройте своего бота от аккаунта, который будет получать заявки, и нажмите **Start / Запустить**. Бот не может первым начать переписку с пользователем.
5. Определите ID нужного чата. Для личного чата это ID пользователя, для группы — ID группы, обычно отрицательный. Это не username, не номер телефона и не ID самого бота.

Если ID неизвестен, его можно получить из `message.chat.id` ответа `getUpdates` после сообщения вашему боту. Выполняйте запрос локальным инструментом с токеном из защищённого ввода, а не вставляйте токен в адресную строку браузера. У бота с действующим webhook метод `getUpdates` недоступен: не отключайте чужую рабочую интеграцию ради проверки. Для существующего бота можно использовать уже известный ID получателя.

Токен даёт управление ботом. Его не включают в код сайта, GitHub, ZIP-архивы, сообщения или скриншоты. Официальные справки: [создание бота](https://core.telegram.org/bots/tutorial), [Bot API](https://core.telegram.org/bots/api).

## 4. Cloudflare: создать сервер отправки в Telegram

Этот раздел обязателен. Создание одной функции в Яндексе не заменяет Worker в выбранной схеме.

### 4.1. Подготовить код и имя

В копии `cloudflare/lead-worker/wrangler.jsonc` задайте уникальное `name`, например `newsite-lead-form`.

В `cloudflare/lead-worker/src/index.ts`:

- Замените домены в `allowedOrigins` на адреса нового сайта.
- Замените название сайта в `leadMessage`, чтобы сообщения не выглядели заявками с photoprobiz.
- Проверьте допустимые пакеты и способы связи: они должны совпадать с новой формой и Яндекс-функцией.

Origin имеет вид `https://newsite.ru`: без пути, без завершающего `/`. Для `www` нужна отдельная запись. Если используете временный GitHub Pages URL, origin — `https://USERNAME.github.io`, без имени репозитория.

### 4.2. Выбрать адрес Worker

Есть два варианта.

**Вариант A: адрес `workers.dev`.** Подходит для первого запуска без переноса домена в Cloudflare. В конфигурации нового Worker удалите скопированный блок `routes` с доменом photoprobiz и задайте:

```jsonc
"workers_dev": true
```

После публикации Cloudflare выдаст точный адрес. Используйте именно его, не составляйте адрес по догадке. URL обработки — выданный адрес плюс `/lead`, URL проверки — плюс `/health`. Доступность `workers.dev` со смартфона не является обязательной для этой схемы, но из Яндекс-функции он должен открываться.

**Вариант B: свой поддомен, как у photoprobiz.** Если DNS-зона нового домена уже активна в Cloudflare, укажите:

```jsonc
"workers_dev": false,
"routes": [
  { "pattern": "api.newsite.ru", "custom_domain": true }
]
```

При публикации Custom Domain создаёт привязку Worker и сертификат. Альтернативный путь в кабинете: **Workers & Pages → нужный Worker → Settings → Domains & Routes → Add → Custom Domain**. Если меняли привязку в кабинете, отразите её в `wrangler.jsonc`, чтобы следующая публикация не вернула старую конфигурацию.

Не копируйте `api.photoprobiz.ru` в настройки другого проекта и не переназначайте его. Если поддомен занят, выберите свободный. Не добавляйте на него обычный CNAME к GitHub Pages: этот адрес предназначен для Worker.

Свой поддомен не обязателен. Ни `workers.dev`, ни собственный домен сами по себе не гарантируют доступ из всех сетей. [Адрес workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/), [Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).

### 4.3. Авторизоваться и опубликовать

Следующие команды выполняются в **копии нового проекта**, не в рабочей папке photoprobiz. В PowerShell перейдите в `cloudflare/lead-worker`, затем:

```powershell
npm.cmd ci
npx.cmd wrangler login
npm.cmd run check
npm.cmd run deploy:dry
npm.cmd run deploy
```

Переходите к следующей команде только после успешного завершения предыдущей. `wrangler login` открывает вход Cloudflare в браузере. Если обратный переход на localhost не работает, можно настроить API-токен с правами публикации Workers для нужного аккаунта; для изменения Custom Domain дополнительно нужны права на соответствующую зону. Не используйте глобальный ключ аккаунта. Токен храните вне проекта и передавайте инструменту через окружение процесса, не через аргументы команд и не через Git.

Команда `deploy` создаёт Worker с именем из конфигурации, если его ещё нет. Отдельно создавать пустой Worker в кабинете не обязательно. В кабинете **Workers & Pages** убедитесь, что появился именно новый Worker. [Команды Wrangler](https://developers.cloudflare.com/workers/wrangler/commands/workers/).

### 4.4. Записать секреты в Cloudflare

Из той же папки выполните по очереди:

```powershell
npx.cmd wrangler secret put TELEGRAM_BOT_TOKEN
npx.cmd wrangler secret put TELEGRAM_CHAT_ID
```

Каждая команда предложит ввести значение. Значения вставляются в приглашение инструмента, а не дописываются в команду. Можно сделать то же в кабинете: **Workers & Pages → новый Worker → Settings → Variables and Secrets**, добавив значения с типом **Secret** и сохранив изменения.

| Имя секрета | Что записать |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота из BotFather |
| `TELEGRAM_CHAT_ID` | ID чата, в который должны приходить заявки |

Для каждого нового Worker секреты настраиваются отдельно. Секреты другого Worker автоматически не наследуются. После сохранения `/health` должен показывать `telegramConfigured: true`, но это лишь наличие настроек. Их правильность подтверждается настоящей тестовой отправкой. [Секреты Workers](https://developers.cloudflare.com/workers/configuration/secrets/).

## 5. Яндекс: подготовить аккаунт и функцию

### 5.1. Аккаунт

1. Войдите в [консоль Yandex Cloud](https://console.yandex.cloud/) через Яндекс ID.
2. Если аккаунт уже использовался для поиска или других сервисов, повторная регистрация не нужна.
3. Проверьте платёжный аккаунт: он должен быть активен и связан с выбранным облаком. Наличие привязанной карты само по себе не доказывает активный статус.
4. Выберите существующий каталог или создайте отдельный каталог для сайта.

При первой регистрации кабинет предложит создать организацию и платёжный аккаунт. Для личного использования можно оформить его как физическое лицо. [Регистрация и платёжный аккаунт](https://yandex.cloud/ru/docs/getting-started/individuals/registration).

### 5.2. Подготовить копию кода под новый сайт

В `yandex/lead-function/index.js` замените:

| Где | Что должно быть для нового сайта |
|---|---|
| `allowedOrigins` | Домены нового сайта, включая нужный `www` и временный адрес |
| `fetchImpl('https://api.photoprobiz.ru/lead', ...)` в ветке `relayMode` | Точный URL нового Worker с `/lead` |
| Заголовок `Origin: 'https://photoprobiz.ru'` в этой же ветке | Origin нового сайта, разрешённый в Worker |
| `packages`, `methods`, `sources`, `parseLead` | Поля и допустимые значения новой формы |
| `service: 'photoprobiz-leads'` | Название нового сервиса для понятной диагностики |
| Текст `message()` | Название нового сайта, если в будущем будет использоваться прямой режим |

**Важная деталь:** в текущем коде адрес Worker задан прямо в JavaScript. Переменная `DELIVERY_MODE` выбирает режим, но не меняет адрес. Просто переименовать функцию в кабинете недостаточно.

Яндекс принимает браузерный Origin нового сайта, а затем сам ставит фиксированный Origin в запросе к Worker. Это не пересылка секретного ключа: Origin — обычный заголовок, который проверяет существующий Worker. Токен Telegram остаётся в Cloudflare.

### 5.3. Сформировать ZIP

В PowerShell из корня **нового проекта**:

```powershell
node --test yandex/lead-function/index.test.cjs
New-Item -ItemType Directory -Path output -Force | Out-Null
Compress-Archive -LiteralPath yandex/lead-function/index.js,yandex/lead-function/package.json -DestinationPath output/leads-yandex.zip -Force
```

В тестах тоже замените адреса на новые ожидаемые значения и сохраните проверки полей, CORS, ошибок и таймаутов. Не удаляйте проверку ради успешного результата. Для упаковки используйте только прошедший тесты код.

В корне ZIP должны лежать **`index.js` и `package.json`**, без внешней папки `lead-function`. `package.json` задаёт CommonJS; это важно для `exports.handler`. В коде нет внешних npm-зависимостей, поэтому `node_modules` в ZIP не нужен.

### 5.4. Создать и настроить функцию

В выбранном каталоге найдите через поиск сервис **Cloud Functions**:

1. Нажмите **«Создать функцию»**.
2. Имя: например, `newsite-leads`. Описание: «Заявки с newsite.ru в Telegram через Cloudflare».
3. Выберите **Node.js 22**, уберите **«Добавить файлы с примерами кода»**, нажмите **«Продолжить»**.
4. Источник кода: **ZIP-архив**. Загрузите `output/leads-yandex.zip`.
5. Заполните параметры:

| Параметр | Значение |
|---|---|
| Точка входа | `index.handler` |
| Таймаут | 15 секунд |
| Память | 128 МБ |
| Сервисный аккаунт | Не выбрано для этой простой версии |
| Сеть | Не выбрано: используется стандартный выход в интернет |
| Переменная окружения | `DELIVERY_MODE` = `cloudflare-relay` |
| Lockbox | Для этого режима дополнительных секретов не требуется |

В режиме `cloudflare-relay` **не нужно повторно записывать токен бота и ID чата в Яндекс**. В photoprobiz они остались от первоначальной попытки прямой доставки, но пересылка через Worker их не использует.

6. Нажмите **«Сохранить изменения»**, дождитесь готовности версии.
7. В **«Обзоре»** включите публичный вызов функции. Посетитель не должен входить в Яндекс для отправки заявки. Публичный вызов не даёт доступа к редактированию функции.
8. Скопируйте **«Ссылку для вызова»**. Она имеет вид `https://functions.yandexcloud.net/FUNCTION_ID`.

В адресе Яндекса не добавляйте `/lead` или `/health`: одна ссылка принимает GET, POST и OPTIONS. Не используйте временную диагностическую точку входа `index.diagnostic`, если она создавалась при отладке.

Если ZIP не загружается, можно создать в редакторе два файла, `index.js` и `package.json`, и вставить в них содержимое подготовленных локальных файлов. Настройки и точка входа остаются теми же. [Создание версии на Node.js](https://yandex.cloud/ru/docs/functions/quickstart/create-function/node-function-quickstart).

## 6. Подключить форму сайта

Для React/Vite в нашей структуре используется `VITE_LEAD_ENDPOINT`. В workflow GitHub Pages, в окружении шага **сборки**, укажите:

```yaml
- name: Build static website
  env:
    VITE_LEAD_ENDPOINT: https://functions.yandexcloud.net/FUNCTION_ID
  run: npm run build
```

Замените `FUNCTION_ID` на ID новой функции. Адрес публичный, его допустимо хранить в репозитории. Для локального просмотра задайте эту же переменную перед сборкой или в локальном файле окружения согласно правилам проекта.

В Vite значение встраивается при сборке. Изменения одной переменной в кабинете после публикации недостаточно: **нужно пересобрать и опубликовать сайт**. Для другого движка найдите реальный обработчик форм; имя `VITE_LEAD_ENDPOINT` не является универсальной настройкой для всех сайтов.

### Формат заявки в текущем шаблоне

Браузер отправляет POST с `Content-Type: application/json`:

```json
{
  "name": "Тест",
  "contact": "+79990000000",
  "contactMethod": "telegram",
  "consent": true,
  "source": "modal",
  "phoneCountry": "RU",
  "packageName": "Минимальный"
}
```

- `contact` всегда содержит телефон с `+` и цифрами, независимо от мессенджера.
- `contactMethod`: `phone`, `telegram`, `whatsapp`, `max_messenger`.
- `source`: `modal` или `inline`.
- `phoneCountry` и `packageName` можно не передавать. Если пакет указан, его значение должно быть разрешено обоими обработчиками.
- `consent` — логическое `true`, а не строка. На сайте оно должно отражать выбор пользователя; обработчики не заменяют интерфейс согласия.

Для другой формы согласованно измените все три части: сайт, Яндекс и Worker. Иначе сервер может отклонить новую форму с HTTP 400.

На клиенте:

- Показывайте успех только после успешного HTTP-ответа **и** JSON `{"ok":true}`.
- Установите ограничение ожидания; в photoprobiz это 12 секунд на клиенте и 8 секунд на следующий сервер в функции.
- Блокируйте повторный клик во время отправки.
- При ошибке сохраняйте введённые поля и показывайте понятное сообщение.
- Примените один и тот же адрес и обработчик ко всем формам: в меню, тарифах, блоках услуг и внизу страницы.
- Переходите к благодарности и PDF только после подтверждения отправки.

## 7. Проверки до и после публикации

### 7.1. Проверка адреса Яндекса

Откройте URL функции без дополнительных путей. Ожидаются `ok: true`, `provider: yandex-cloud`, `deliveryMode: cloudflare-relay`.

Поле `telegramConfigured` относится к наличию Telegram-переменных в Яндексе. **В режиме пересылки значение `false` допустимо**: настоящие секреты находятся в Worker. GET не проверяет доставку сообщения.

Повторите открытие на телефоне: выключите Wi-Fi, отключите VPN и проверьте через мобильного оператора.

### 7.2. Проверка CORS

Из PowerShell, заменив значения:

```powershell
$leadEndpoint = 'https://functions.yandexcloud.net/FUNCTION_ID'
$siteOrigin = 'https://newsite.ru'
$preflight = Invoke-WebRequest -UseBasicParsing -Uri $leadEndpoint -Method Options -Headers @{
  Origin = $siteOrigin
  'Access-Control-Request-Method' = 'POST'
  'Access-Control-Request-Headers' = 'content-type'
}
$preflight.StatusCode
$preflight.Headers['Access-Control-Allow-Origin']
```

Ожидается статус 204 и разрешённый Origin нового сайта. Для чужого Origin обработчик должен отклонять отправку.

### 7.3. Тестовая доставка

Следующая команда **отправляет настоящее тестовое сообщение владельцу бота**. Выполняйте её после настройки своего получателя:

```powershell
$testLead = @{
  name = 'Тест нового сайта'
  contact = '+79990000000'
  contactMethod = 'phone'
  consent = $true
  source = 'inline'
  phoneCountry = 'RU'
} | ConvertTo-Json -Compress

Invoke-RestMethod -Uri $leadEndpoint -Method Post -Headers @{ Origin = $siteOrigin } -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($testLead))
```

Нужны оба подтверждения: ответ `ok: true` и сообщение в правильном Telegram-чате с названием правильного сайта. Если запрос завершился таймаутом, сначала посмотрите Telegram: повторная попытка может создать дубликат.

### 7.4. Публичный сайт

1. Выполните тесты проекта и production-сборку с новым endpoint.
2. Опубликуйте сайт. На GitHub дождитесь успешного завершения Actions, а не только успешного `git push`.
3. Убедитесь, что публичная сборка содержит URL новой Яндекс-функции.
4. Отправьте заявку из обычной и всплывающей формы; проверьте выбор тарифа и мессенджера.
5. Проверьте сообщение, страницу благодарности и загрузку PDF.
6. Повторите отправку опубликованной формы через мобильную сеть без Wi-Fi и VPN. Одного открытия health-страницы недостаточно.
7. По возможности повторите с другой SIM и домашним провайдером.

До завершения проверок не отключайте рабочую прежнюю доставку. В новой схеме Worker также нельзя отключать после тестов — он продолжает отправлять сообщения.

## 8. Что делать с DNS и Cloudflare после подключения

Если сайт уже работает на своём домене, **не меняйте NS-серверы только ради формы**. При использовании адреса `workers.dev` новый домен в Cloudflare не требуется.

Для photoprobiz роли Cloudflare разделены:

- DNS основного сайта остаётся в Cloudflare; записи GitHub Pages работают в режиме DNS only.
- Worker на `api.photoprobiz.ru` обслуживается Cloudflare и нужен для серверной доставки.
- Браузер отправляет форму на `functions.yandexcloud.net`, а не на `api.photoprobiz.ru`.

Отключение ECH и собственный домен ранее не обеспечили доступ к API через Beeline. В этой инструкции решение — изменение маршрута заявки через Яндекс. Не обещайте исправить любую блокировку одним переключателем Cloudflare.

## 9. Ошибки и порядок диагностики

| Симптом | Что проверить |
|---|---|
| URL Яндекса не открывается | Публичность функции, активную версию, статус аккаунта, доступ через другую сеть |
| Ответ содержит `deliveryMode: telegram` | Не задана или ошибочно написана `DELIVERY_MODE=cloudflare-relay`; после изменения нужна новая версия |
| GET работает, а POST возвращает 403 | Origin браузера в allowedOrigins Яндекса; для Worker — фиксированный Origin серверного запроса |
| HTTP 400 | Формат JSON, телефон, согласие, `source`, пакеты и значения мессенджеров во всех трёх частях |
| HTTP 415 | Заголовок `Content-Type: application/json` |
| `RELAY_DELIVERY_FAILED` | URL Worker с `/lead`, его публикацию, разрешённый Origin, секреты бота и доступ к Telegram |
| `RELAY_TIMEOUT` | Соединение Яндекс → Worker или задержку дальнейшей доставки; увеличение клиентского таймаута не исправляет недоступную сеть |
| `TELEGRAM_TIMEOUT` от Яндекса | Включён прямой режим; для этой инструкции нужен `cloudflare-relay` |
| Worker сообщает `TELEGRAM_NOT_CONFIGURED` | В этом конкретном Worker не сохранены оба Telegram-секрета |
| Ответ успешный, сообщение не найдено | Правильный ли чат/бот; проверить шаблон сообщения и серверное подтверждение Telegram, не только код 200 |
| Новый endpoint работает, форма всё ещё не работает | Старая сборка или кеш, забытая форма с другим адресом, ошибка CORS, отсутствие пересборки |
| Клиент видит старую страницу | Обновить страницу, проверить публикацию и фактический JS-файл в браузере |

Проверяйте цепочку по частям: браузер → Яндекс, Яндекс → Worker, Worker → Telegram. Не выводите в логи токены, номера телефонов или полные тела заявок. Текст ошибки сетевого инструмента может содержать URL с токеном — его тоже нельзя публиковать.

## 10. Стоимость, ограничения и дальнейшее усиление

На дату подготовки у Cloud Functions есть ежемесячный free tier: 1 миллион вызовов и 10 ГБ·часов выполнения на платёжный аккаунт. Для нескольких сайтов лимит общий, а OPTIONS и проверки доступности тоже расходуют вызовы. Сверх лимитов и за дополнительные ресурсы возможны списания. Стартовый грант — отдельная временная акция, не обещание бесплатной работы навсегда. [Актуальные бесплатные лимиты](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier).

Перед запуском проверьте также текущие [лимиты Cloudflare Workers](https://developers.cloudflare.com/workers/platform/limits/). Настройте уведомления о расходах в Яндексе; бюджетное уведомление само по себе не является жёстким ограничителем потребления.

### Сколько заявок в месяц помещается в бесплатный объём

**Фиксированного лимита «заявок на сайт» у Яндекса нет.** Есть бесплатный объём запросов и вычислений. Платное использование сверх него возможно при действующем платёжном аккаунте и в пределах технических квот.

Два основных бесплатных объёма Cloud Functions:

| Что учитывается | Бесплатный объём за календарный месяц |
|---|---|
| Запуски функции | 1 000 000 |
| Выделенная память × время выполнения | 10 ГБ·часов |

Они расходуются одновременно. Функция с памятью 128 МБ использует `128 / 1024 = 0,125 ГБ`. Значит, 10 ГБ·часов соответствуют примерно **80 часам суммарной работы**, или **288 000 секундам**. Ожидание ответа следующего сервера входит во время работы функции; фактическое время каждого вызова округляется вверх до 100 мс.

Ориентировочный верхний расчёт только для обработки заявок при памяти 128 МБ:

| Средняя учитываемая длительность одного POST | Заявок до расходования 10 ГБ·часов |
|---|---|
| 1 секунда | около 288 000 |
| 2 секунды | около 144 000 |
| 5 секунд | около 57 600 |

Это расчёт, не обещанный объём реальной доставки. Часть бесплатного ресурса уйдёт на OPTIONS, GET-проверки, неуспешные запросы и другие функции. Время 1,45 секунды из теста photoprobiz измерялось снаружи и не является замером тарифицируемой длительности; для точного прогноза используйте метрики функции и Billing.

Новый посетитель обычно вызывает сначала OPTIONS, затем POST. Поэтому миллион вызовов не равен миллиону заявок. Кеширование preflight уменьшает число OPTIONS при повторных запросах. При обработке заявки за 1–5 секунд бесплатный объём вычислений, вероятно, закончится раньше миллиона вызовов.

### Если сайтов несколько

**Free tier выдаётся на платёжный аккаунт, не на домен, функцию, каталог или облако.** Все Cloud Functions, связанные с одним платёжным аккаунтом, расходуют общий объём. Отдельная функция для каждого сайта удобна для настройки и диагностики, но не создаёт отдельный бесплатный миллион.

Пример: три сайта получают по 1 000 заявок в месяц. Итого 3 000 заявок. Если каждый POST занимает 2 секунды, а каждый OPTIONS — 0,1 секунды, получатся примерно:

- 6 000 вызовов: 0,6% бесплатного миллиона;
- `3000 × 2,1 × 0,125 / 3600 = 0,21875 ГБ·часа`: около 2,2% бесплатного вычислительного объёма.

Пример предполагает один OPTIONS на заявку и отсутствие прочих вызовов. Другие функции того же платёжного аккаунта тоже учитываются. Яндекс Поиск и прочие сервисы имеют собственные тарифы; миллион Cloud Functions не является единым лимитом всех сервисов Яндекса. [Правило общего счётчика](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier), [тарификация вычислений](https://yandex.cloud/ru/docs/functions/pricing).

### Ограничение Cloudflare в этой цепочке

На Workers Free действует **100 000 запросов в сутки на аккаунт**, общий лимит всех его Workers. Он сбрасывается в полночь UTC; при превышении Cloudflare возвращает ошибку 1027. Это суточный предел бесплатного плана, его нельзя считать месячным запасом для одного пикового дня.

Яндекс обрабатывает браузерный OPTIONS самостоятельно. В Worker уходит один запрос на одну прошедшую валидацию заявку, плюс отдельные проверки и обращения к другим Workers вашего аккаунта. При небольшом потоке заявок у этой схемы большой запас, но лимиты обеих платформ нужно учитывать совместно. [Лимиты Workers Free](https://developers.cloudflare.com/workers/platform/limits/).

Текущая схема синхронная: постоянного хранилища заявок, очереди и гарантированных повторов нет. При сбое после фактической отправки результат может быть неопределённым. Для более строгой надёжности отдельно добавляют сохранение заявки, уникальный ID, очередь и повторы с защитой от дублей.

Origin/CORS не является полноценной защитой от спама: произвольный HTTP-клиент может подставить заголовок. При росте нагрузки отдельно настраивают ограничения частоты и защиту формы. Для закрытия прямого доступа к Worker можно добавить общий серверный секрет на стороне Яндекса и Worker; **в нынешнем шаблоне такой проверки нет**, одной переменной окружения недостаточно. Секрет никогда не передаётся в браузер.
